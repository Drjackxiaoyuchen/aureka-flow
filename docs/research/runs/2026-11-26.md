## Implemented and locally reproduced

The pinned FlowIO 1.3.0 TEXT parser removes every dollar character before splitting pairs. A generated file containing distinct `FITC$-A` / `FITC-A` detectors therefore became duplicate channels and was rejected by the previous browser importer; creator values also lost dollars. Some escaped separators remain doubled in upstream labels. Native HEADER inspection preserved dollars but decoded UTF-8 as Latin-1, while native event analysis used altered FlowKit labels. These are locally reproduced parser behaviors on explicit synthetic bytes, not observations of BD hardware exports.

Moved Aureka's existing bounded HEADER/TEXT reader into a shared standard-library module and added UTF-8 decoding with the pinned reader's whole-segment Latin-1 fallback. Browser and native analysis now validate primary TEXT first, retain literal values and reject duplicate keys/ambiguous detector names. FlowIO still decodes DATA with strict offsets; validated literal metadata and channel labels are supplied through public FlowData attributes before FlowKit builds mappings, applies gain/time preprocessing or compensates events. A guard refuses disagreement in DATA-decoding fields. No input bytes or dependency pins change. The frozen-reference receipt now hashes this adapter too.

The imported exact names propagate to stain labels, matrix detector references, project/metadata exports and event CSV columns. Source hashes and zero-based event order remain intact. Old projects that relied on altered names require explicit review; no guessed migration is introduced. The optional external `.wsp` replay path remains independently scoped.
