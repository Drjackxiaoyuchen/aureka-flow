## Reproduced problem and change

FlowIO 1.3.0 assigns `event_count` from `$TOT` while reading the whole declared DATA segment. Before the fix, independently packed files with three actual events but `$TOT` set to 1, 2 or 4 were accepted by the browser engine. The sample advertised that declaration while its source array still had three rows. This could make counts and fraction denominators inconsistent. A `$TOT=0` file with real DATA instead reached the browser's misleading no-events error. A partial row could reach a generic reshape error.

The shared import adapter now verifies that the decoded scalar count is exactly `$TOT × $PAR` before FlowKit constructs/preprocesses a sample. On mismatch it reports declared event/parameter counts and decoded values, requiring a complete re-export. It never truncates, pads, rewrites metadata or changes event order. The check uses the pinned decoder's public event array and adds no second DATA decoder or dependency. Source hashes and settings remain unchanged. HEADER/TEXT-only inspection remains explicitly outside event validation.
